# tobe-process-map v1.4.0 실행 최적화 QA

검증일: 2026-11-11 (KST) · 기준 버전: v1.3.1

## 이번 수정의 대상

Excel을 올려 HTML·Excel을 생성하는 대화에서 작업 한도가 소진되어 “계속”을 반복해야 하는 문제를 다뤘다. 사용자 제공 테스트 조건은 Claude, v1.3.1, “OPUS 5.5 중간”이다. 해당 실행의 로그·후보 파일은 없어 Claude의 실제 호출 횟수를 재현하거나 감소율을 측정하지는 못했다.

기존 최적화는 브라우저 검사 시간에 주로 집중했고, 설계 작성량과 대기 후 재개 비용까지 충분히 줄이지 못했다. 이번 버전은 실행 수명, 중복 작성, 오류 수정 왕복, 기본 작업 지침을 함께 바꿨다. HTML 버튼 동작은 변경하지 않았다.

## 확인한 원인과 수정

| 확인한 문제 | v1.4.0 처리 |
|---|---|
| v1.3.1은 호출 대기가 끝나면 남은 QC 묶음의 예약·최종 인증을 더 진행하지 않음 | 기본 run이 별도 작업자를 시작하고 전체 QC와 인증까지 이어감. 대기 종료는 작업 종료가 아님 |
| 설명·이름을 상세창과 흐름 안내에 중복 작성 | authoring.json의 내부 참조, 업무별 narrative, 명시적인 투어 순서를 정식 design.json으로 전개 |
| 문서는 자동 보완을 안내하지만 검증이 먼저 실행돼 별도 fill·재시도 필요 | run에서 누락된 기계적 필드를 먼저 보완. 작성한 값·명시적 빈 배열·업무·연결은 보존하고 변경 전 파일 백업 |
| 입력 오류를 첫 번째 항목부터 하나씩 수정하며 재실행 | 입력 오류 전체를 한 번에 진단. 입력 준비 오류에는 prepare 재실행을 안내 |
| 큰 원천 JSON 반복 읽기, 일반 생성에 개발용 검사와 확인 절차 추가 | 모든 업무 필드를 보존한 단계별 자료 제공. 일반 생성은 prepare → 설계 작성 → run. 개발용 회귀검사·선택형 사전 확인을 기본 경로에서 구분 |

v1.3.1의 대기 문제는 소형 재현에서도 확인했다. `run --wait 0` 종료 후 12초가 지나도 두 QC 묶음이 대기 상태였고 다시 run을 호출해야 완료됐다. v1.4.0에서는 최초 run 이후 별도 run/status/QC 호출 없이 완료됐다. 상태 파일을 읽어 진행만 관찰했으며, 그 읽기가 작업을 진행시키지는 않았다.

## 결과 보존과 검증

| 검증 | 결과 |
|---|---|
| 전체 회귀검사 | 223개 통과 |
| 완전한 Excel 단일 입력 → HTML·Excel·manifest | 소형 4개 업무 fixture 성공. 원본 필드·ID 보존. 실제 Chromium 24개 화면·7개 패널 통과 |
| 원본 HTML + compact authoring → 최종 인증 | 24개 화면·7개 패널, QC 4개 묶음 모두 통과. 최초 run 뒤 추가 실행·상태조회·QC 호출 0회 |
| 공통 As-Is 화면 | Lv.4~6 공유 렌더러 검사 통과. 원천 대응·공통 UI 오류 0 |
| 설명 참조 전개 | 기존 설계로 정확히 왕복. 생성 HTML·PMD·Excel 표의 동일성 검사 통과 |
| 화면 기능 유지 | engine.js, shell.html, phrasebook.json, b_review_widget.html이 v1.3.1과 바이트 단위로 동일 |
| 입력 보존 | 누락 ID·연결을 추측하지 않으며, 해결되지 않은 원천 오류는 계속 차단 |

소형 통합 검증의 To-Be는 Agent 2개와 사람 판단 1개다. 기존 검증용 설계를 사용한 실행 검증이며, 357개 고객 업무를 새로 설계하는 모델의 소요 시간까지 측정한 결과는 아니다. 원본 HTML을 포함한 실행은 run 반환 후 약 10.6초에 자동 완료됐다. 이 값은 해당 소형 fixture의 실측치다.

구조 재설계 근거, 독립된 사람 판단, 승인·반려 연결, 원본 배치·화살표 보존, 문구·경고 검토, 전체 브라우저 QC, HTML/Excel 일치, 현재 파일 해시에 묶인 인증 기준을 유지했다. 경고를 자동 면제하거나 검사 화면을 줄여 통과시키지 않았다.

## 작성·읽기 자료 실측

| 대상 | 변경 전 | 변경 후 | 의미 |
|---|---:|---:|---|
| 기존 205개 업무 CRM 설계, compact JSON | 442,399 bytes | 411,638 bytes | 30,761 bytes 감소(6.95%). 반복 설명 16,238자 재작성 제거 |
| 357개 원천 업무의 A4/A5/A6 읽기 자료 | 456,627 bytes | 265,194 bytes | 41.9% 감소. 모든 업무 필드는 손실 없이 복원 가능 |

첫 비교는 동일한 compact 직렬화 기준이다. 들여쓰기한 파일 크기나 전체 모델 토큰 감소율로 바꾸어 해석하면 안 된다. 205개 업무 설명과 18개 Orchestrator 설명의 정확히 같은 부분을 참조했으며, 서로 다른 설명은 유지했다. 두 비교 모두 Claude의 작업 횟수·“계속” 횟수 측정값은 아니다.

첨부 원본 Excel의 단독 준비에서는 357개 행 중 ID 누락 56건, 연결 참조 31건, 단계 이름 충돌 2건, Lv.5 부모/이름 충돌 1건을 한 번에 보고했다. 같은 범위의 원본 HTML을 함께 사용하면 357개 업무를 모두 준비하며 오류 0건, 기존 참조 경고 31건을 기록한다. 이 결과를 팀이 최근 테스트한 Excel의 상태라고 단정하지 않는다. 완전한 Excel은 HTML 없이도 처리할 수 있다.

## 적용 방법과 한계

Claude에 설치한 v1.3.1 스킬을 이 ZIP으로 교체한다. As-Is Excel을 입력하고 원본 HTML도 있으면 함께 제공한다. 기존 첨부나 답변을 반복 요청하지 않도록 지침을 정리했다. 설치 경로와 다운로드 출력 경로는 사용 환경에 맞추며, Claude의 일반 출력 경로는 `/mnt/user-data/outputs/<작업명>`이다.

작업자는 실행 환경이 유지되는 동안 자동 진행한다. 플랫폼이 프로세스를 종료하거나 도구·컨텍스트 한도 자체를 막는 경우까지 제거하는 기능은 아니다. 실제 설계 오류에는 수정이 필요하고, 자료가 부족한 핵심 판단에는 질문이 필요할 수 있다. 한 응답 안의 완료 또는 “계속” 횟수 0회를 보장하지 않는다.

ZIP 교체만으로 이전에 생성한 HTML이 바뀌지는 않는다. 기존 design.json을 재사용하려면 새 작업 폴더에서 원천을 준비하고 해당 설계를 가져와 검증한다. 선택적인 authoring.json은 중복 작성만 줄이며 설계 판단·승인·흐름을 대신 추측하지 않는다.

검증 환경: Python 3.12, openpyxl 3.1.5, Playwright 1.62.0, Chromium 156, Linux. 기계 판독 요약과 주요 파일 해시는 QA_RESULTS.json에 포함했다. 고객 원본 파일·실제 업무 설계·작업 로그는 배포 ZIP에 포함하지 않았다.
