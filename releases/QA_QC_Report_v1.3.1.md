# To-be Process Map v1.3.1 — As-Is 공통 화면 수정 QA

검토일: 2026-11-10. v1.3.0을 기준으로 수정했다. v1.2.0과 v1.3.0의 원본 HTML iframe 표시는 요구사항을 잘못 해석한 구현이었으며 폐기했다.

## 수정 결과

As-Is와 To-Be는 같은 렌더러, 박스·글꼴·레인 스타일, 레벨/단계 선택, 보기, 확대/축소, 상세 창, 편집, 저장 기능을 사용한다. 입력 As-Is HTML은 프로세스 구조와 배치의 근거로만 사용하며 원본 페이지 자체를 표시하지 않는다.

- 입력 HTML에서 실제 박스 위치, 원천 업무 대응, 연결 방향·유형·경로·점선·화살촉, 합류 지점, 실제 표시 라벨을 가져온다. 공통 박스 크기에 맞춘 양의 배율·이동 변환으로 상대 배치를 유지한다.
- 원본에 없는 연결을 추가하거나 분기·병렬·조건·환류를 임의로 순차화하지 않는다. 미지원 형식과 모호한 중복 연결은 명시적으로 중단한다.
- 공동 담당 조직에 반복 표시된 박스는 원본 업무 상세로 연결하며 고유 업무 수에 중복 집계하지 않는다.
- 원본에서 보이지 않던 일반 연결선 설명을 새로 표시하지 않는다. 실제 보이는 라벨은 위치와 함께 표시하며, 전체 의미·문구는 연결 데이터와 상세 정보에 남긴다.
- 원본 바이트·데이터·배치·투영 결과를 검증한다. 브라우저 저장 때 숫자 표현이 `1.0 → 1`로 바뀌어도 의미가 같은 값의 해시 검증은 유지된다.
- As-Is도 전체 화면·상세 창 QC에 포함한다. iframe 존재, 공통 조작부 불일치, 원천 대비 노드/연결/유형/경로/라벨 변경을 실패로 처리한다.
- Excel에 원천 노드·연결 유형·배치·경로 검토표를 추가하고 HTML/Excel 및 복원 데이터의 일치를 검사한다.
- v1.3.0의 일괄 실행, 중단 후 재개, 변경 시 캐시 무효화, 구조 재설계 및 사람 개입 분리 검증을 유지한다.

## 최종 검증

| 검사 | 결과 |
|---|---|
| 전체 회귀 테스트 | **171개 통과** |
| 실제 CRM As-Is 화면 | **54개 통과**: 3개 레벨 × 2개 보기 × 전체/8개 단계 |
| 두 탭 공통 UI | **43개 검사 통과**, 12개 화면 비교, 런타임 오류 0 |
| 실제 CRM As-Is 상세 창 | **534개 통과**: Lv.4 38, Lv.5 131, Lv.6 365 |
| 원본 브라우저와 독립 대조 | **534개 박스·542개 고유 표시 경로 일치**, 누락/추가 0 |
| 양쪽 탭 편집·저장·다시 열기 | 문구 수정값 유지, iframe 없음 |
| 입력부터 최종 인증까지 | 실제 원본 참조 예제로 prepare → run 자동 완료, **24개 화면·7개 상세 창 통과**, manifest passed |
| Excel | 원천 유형·경로 복원 일치, 검토 표 변경 시 변조 검출 |

CRM 원천은 고유 Lv.6 업무 **357개**다. 화면의 365개 박스에는 공동 담당 조직에 반복 표시한 8개 박스가 포함된다. 원본 Lv.4/5도 각각 고유 34/123개와 표시 38/131개를 구분했다. 상위 단계 8개는 별도 집계다.

실제 CRM의 분기·합류 및 Monthly/Weekly와 Daily 수집·통합의 병렬 배치를 확인했다. 조건부·환류와 실제 표시 라벨은 별도 예제로 검증했다. 고의로 경로·유형·라벨·헤더 높이를 바꾸는 회귀 검사에서 실패가 검출됐다.

원본에 이미 존재하는 공유 선분은 최대 35개 구간이다. 원천의 연결 쌍·좌표 구간과 표시 구간이 정확히 같은 경우에만 원천 관찰값으로 별도 기록했다. 원본 경로를 바꾸어 없애지 않았으며, 신규 겹침·박스 관통·잘림·유형 변경은 계속 차단한다. 최종 CRM QC의 신규 오류, 원천 불일치, 공통 UI 오류, 스크립트 오류, 잘림, 라벨 겹침은 모두 0이다.

검수 중 발견한 점선 CSS 덮어쓰기, 긴 단계 제목 넘침, 불필요한 라벨 표시도 수정했다. 실제 CRM 검수 HTML은 기존 To-Be 데이터와 원천 As-Is를 결합한 렌더링 회귀 검증용이며, 새로운 CRM To-Be 설계를 승인한 결과물은 아니다.

## 적용 방법

1. 기존 스킬 대신 **v1.3.1 ZIP**을 설치한다.
2. 동일한 As-Is Excel·HTML로 새 work 폴더에서 prepare한다. 기존 설계가 있으면 design.json을 보관한 뒤 새 작업으로 옮겨 재검증한다.
3. run으로 HTML·Excel을 다시 생성하고 manifest가 passed인지 확인한다.

기존에 생성된 HTML 파일은 ZIP 교체만으로 자동 수정되지 않는다. 새 버전으로 재생성해야 한다. 설치와 명령은 SKILL.md 및 references/workflow.md를 따른다.
